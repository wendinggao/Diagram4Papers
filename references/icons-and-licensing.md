# Select assets without lowering the visual standard

## Selection and fallback

For a new figure, search Flaticon live for the actual operation/data and a coordinated illustrated color family. Inspect candidate artwork, not search snippets alone. Match semantic specificity, contour, internal detail, palette vitality, perspective and visible-subject size to the visual target. Use icons beyond headers where they explain an operation/object; more icons are not automatically better.

Select the family early enough to affect composition. Assign an illustration to a concrete role: introduce a resource, distinguish candidate actions, mark an execution/checking operation, or identify an output artifact. Place it beside that role's actual payload. Alternate illustrated groups with editable scientific forms so the figure has both visual richness and method-specific detail. When increasing illustrated density, increase the meaningful visible footprint inside sparse regions, not only the number of small symbols around titles.

Use legitimately available SVG first. If PNG is the permitted available format, retain its source record and trace with a local vectorizer when useful; inspect enlarged and final-size rendering, preserve transparency and verify real paths. Do not bypass access controls. A raster inside SVG is not vectorization.

If one asset's grant or availability is unsuitable, search another author/family/source. A generic concern about public release is not a reason to replace all professional art with sketches. [Streamline's official open-source color collection](https://github.com/webalys-hq/streamline-vectors), whose repository includes its own license, is a mature full-color alternative. Match it visually: gradients, perspective or softness may differ from lineal-color artwork. The bundled subset demonstrates a declared fallback, not a universal choice.

An original icon is an intentional asset choice, not an automatic escape hatch. Review comparable silhouette, detail, contour and final-size quality. Scientific diagrams are different: author graphs, geometry, correspondence lines, traces and state payloads directly so meaning stays editable. Do not replace them with stock icons.

## Provenance ledger

Use JSON with an `assets` list. External entries record `id`, relative `file`, `sha256`, `title`, `author`, `source_url`, `license`, `license_url`, `origin: external`, `distribution`, and `transformations` (empty for exact downloads). For original art record `origin: original`, authorship and deliberate purpose. Script embedding does not imply original authorship.

`Figure.asset()` verifies bytes, propagates asset ID/origin and embeds SVG. `Figure.icon()` needs explicit provenance for final work. The checker verifies ledger/payload consistency; it cannot certify aesthetics or legal suitability. Create an asset board when adopting a family; inspect source thumbnails and final-size uses. Record real findings, not a boolean claiming aesthetic adequacy.

Preserve original colors. Try visible-subject size, placement and surrounding light areas before editing art. Do not recolor every icon to match its module.

## Separate distribution questions

Check each source's actual terms for its intended use. Skill source code, reusable icon library, an example draw.io with extractable SVGs, and flattened PNG are distinct deliverables. Keep required notices beside redistributed art; the skill's MIT license does not replace them. Tracing/recoloring does not establish distribution rights. Do not bundle a font.

Solve a source-specific constraint with a suitable alternative. If rights remain unresolved, retain working material privately and state the affected deliverable. Do not imply approval of a crude substitute or silently deliver a lower-quality final figure.

The public examples use Streamline Ultimate Colors SVGs with attribution in `assets/streamline/`. Live Flaticon search informs preferred style; no Flaticon file is bundled. Recheck current [Flaticon terms](https://www.flaticon.com/legal) when using its assets rather than treating this guide as legal permission.
